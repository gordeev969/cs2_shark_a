# Архитектура frontend: Feature-Sliced Design

Frontend использует React, TypeScript, Vite, Tailwind и Recharts. Точка входа `src/main.tsx` подключает приложение. Слои имеют следующий порядок зависимостей:

```text
app → pages → widgets → features → entities → shared
```

Модуль может импортировать свой срез и нижележащие слои. Импорт вышележащего слоя запрещён. Разные срезы одного слоя не импортируют друг друга: композиция выполняется в слое выше. Например, `entities/match` не импортирует `entities/player`; страница матча объединяет нужные сущности.

| Слой | Ответственность в этом проекте |
| --- | --- |
| `app` | Инициализация, маршрутизация, глобальные стили и провайдеры авторизации и настроек |
| `pages` | Dashboard, импорт, список и отчёт матча, поиск и профиль игрока, настройки, Steam-вход, подключение CS2, 404 |
| `widgets` | Оболочка приложения, история игрока с графиком, блоки статистики |
| `features` | Загрузка демки, выбор своего игрока, изменение личных настроек, Steam session, CS2 connect/sync |
| `entities` | Представление матча, игрока, auth session, CS2 connection и настроек; таблица матча и сообщения о локальной истории |
| `shared` | HTTP-клиент, транспортные типы API, общие UI-компоненты и форматирование |

Срезы располагаются в `pages`, `widgets`, `features`, `entities`. Внутри среза используются сегменты `ui`, `model`, `lib`, если они нужны. В `app` и `shared` срезов нет; эти слои организованы по техническим сегментам. Не создаются пустые папки для формального заполнения схемы FSD.

## Публичный API

Каждый срез открывает разрешённые импорты через `index.ts`. Внешний потребитель импортирует `@/entities/match`, а не `@/entities/match/ui/Scoreboard`. Внутри одного среза допустимы относительные импорты его реализации. Алиас `@/` обозначает `src/`.

```ts
// Страница комбинирует нижележащие срезы через их публичный API.
import { Scoreboard } from '@/entities/match'
import { SelectOwnPlayer } from '@/features/select-own-player'
```

Транспортные структуры находятся в `shared/api/contracts.ts`. Это описание JSON-контракта сервера: nullable-поля, структура ответа, статусы импорта. Здесь нет правил подсчёта статистики, расчёта ADR или аналитики. Численные правила и база данных принадлежат backend; frontend отображает полученный результат и причины отсутствующих данных. Общий HTTP-клиент и hook загрузки находятся в `shared/api/client.ts`.

Провайдер приложения передаёт настройки через React context; его контекст объявлен в нижележащем модуле сущности настроек. Поэтому features и widgets не зависят от `app`.

## Проверка границ

Локальное правило ESLint `frontend/scripts/fsd-rule.js` проверяет:

- запрет импорта верхнего слоя;
- запрет импорта соседнего среза того же слоя;
- использование публичного `index.ts` чужого среза;
- обычные, относительные и динамические импорты, а также реэкспорты.

`frontend/tests/architecture.test.ts` проверяет разрешённые и запрещённые случаи. `npm --prefix frontend run lint` применяет правило к реальным исходникам. `npm --prefix frontend test` запускает архитектурные и форматирующие тесты. Правило ограничивает зависимости модулей; семантическое назначение нового кода проверяется при ревью.

AuthContext объявлен в `entities/auth`; загрузка сессии и композиция guard/SettingsProvider принадлежат `app`. `features/steam-session` выполняет logout и открывает настоящий Steam OpenID endpoint. `features/connect-cs2` управляет подключением и синхронизацией, а страница дашборда композирует действия и сущности через public APIs. CSRF transport находится в shared HTTP client; cookie сессии HttpOnly и не читается JavaScript. Ручной XHR импорт также получает CSRF header.
