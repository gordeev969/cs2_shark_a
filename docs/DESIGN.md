# Обновление интерфейса

Последняя доработка выполнена по [Taste Skill](https://github.com/Leonxlnx/taste-skill/blob/main/skills/taste-skill/SKILL.md). Аудит и применимые к дашборду решения описаны в [TASTE_AUDIT.md](TASTE_AUDIT.md). Поверхности стали спокойнее, акцентный градиент выделяет последний матч, метрики дашборда объединены в строку с разделителями. Визуальные токены и адаптивность этой доработки находятся в `app/styles/refinement.css`. Skeleton страницы не показывает числовых данных; загрузка, ошибка и повторный запрос сохраняют доступные статусы.

Главный экран показывает выбранного игрока, последний матч и ключевые показатели вместо общего рекламного баннера. Числа берутся из прежних API-контрактов: суммарные K/D/A профиля, rolling K/D, ADR, HS% и K/R, подтверждённый итоговый счёт матча. Frontend не вычисляет игровые метрики.

Визуальный стиль адаптирован по публичному интерфейсу [Wope](https://wope.com/): почти чёрный фиолетовый фон, мягкое сиреневое свечение, градиентные заголовки, полупрозрачные рамки и стеклянные кнопки-пилюли. Эти приёмы применены к дашборду, матчам, профилям, входу и настройкам. Цвета побед и поражений сохраняют самостоятельное значение. Навигация разделена на аналитику и пространство; заголовки, карточки, таблицы и футер используют общий масштаб шрифтов и отступов.

Для заголовков, названия приложения и крупных показателей используется Onest: его округлые плотные формы ближе по характеру к Rebond Grotesque на Wope. Небольшие подписи и таблицы используют Manrope. Оба открытых шрифта поддерживают кириллицу, размещены локально и имеют `font-display: swap`. Лицензии SIL OFL находятся в `frontend/public/fonts/Onest-OFL.txt` и `frontend/public/fonts/OFL.txt`. Крупные значения K/D/A и счёт используют табличные цифры. Визуальное оформление реализовано нашим CSS; логотипы, изображения, шрифты и скрипты Wope не используются.

Подсветка карточек следует за мышью через CSS-переменные. Обработчик в `shared/lib/pointer-glow.ts` не вызывает React-перерисовку на каждом движении и пропускает касания. При `prefers-reduced-motion` эффект отключён, а в режиме принудительных цветов градиентные заголовки остаются читаемыми.

Основная кнопка переносит слои CSS «Unlimited trial for 14 days» с публичной страницы [Wope](https://wope.com/), проверенной 2026-10-10. Общие `GlowLink` и `GlowButton` экспортируются из `shared/ui`; ссылка/кнопка размещена внутри отдельной обёртки, а декор — соседними слоями за поверхностью контрола. Сохранены оригинальная SVG-маска частиц (`wope-particles.svg`, извлечена из CSS mask data URI), её размер/фаза повторения, квадратный контейнер, две разные схемы transform (rotate и translate+rotate), маска рамки с padding 1 px, конус с границами 0°/60°/310°/360°, цикл 2s linear, blur 8 px/opacity 0.12, радиальные фоны и hover до opacity 0.7 за 1s. Лишнее фиолетовое свечение предыдущей версии удалено. Текст остаётся русским, шрифт — выбранный Onest.

Анимация находится в `shared/ui/glow-action.css`. Декор имеет `aria-hidden` и не перехватывает клики. Остановка при reduced motion/disabled и системные цвета при forced colors добавлены для доступности. Focus-рамка отображается на внешней обёртке, чтобы overflow не обрезал её.

По просьбе пользователя цикл замедлен с исходных 2s до 4s: рамка, свечение и частицы движутся синхронно с постоянной скоростью, без остановки на стыке оборотов. Для трёх вращающихся слоёв добавлен `will-change: transform`. Геометрия, маски и hover сохранены.

После аудита Taste Skill верх текстового градиента кнопки осветлён с alpha 0.3 до 0.72 для читаемости; высота кнопки на телефоне составляет минимум 44px. Историческая сверка ниже относится к исходному оформлению Wope до этих изменений.

Сверка с извлечённым CSS Wope до замедления выполнена на одинаковой геометрии 240×40 и фоне #0a0118 в восьми фазах 0–1750 ms. Для численной сверки скрыт текст, чтобы шрифты не влияли на сравнение эффекта. Максимальное отличие RGB — 1/255, среднее — менее 0.003/255; результаты в `wope-cta-phase-comparison.json`. В историческом [GIF сравнения](screenshots/wope-cta-comparison.gif) слева извлечённый CSS Wope, справа компонент приложения с исходным циклом 2s; обе подписи используют один текст и Onest для сравнения эффекта.

Публичный режим просмотра обозначен в статусе и компактном раскрываемом уведомлении. Авторизация Steam и импорт своих файлов по-прежнему требуют серверной версии. Отсутствующие значения, неизвестная дата игры и недостаточная история не заменяются вымышленными показателями. Пустой график показан компактным пояснением.

Новый FSD-срез `widgets/dashboard-overview` отображает профиль и последний матч; композиция выполняется на странице. Основные стили сохраняются в `app/styles/index.css`, визуальная доработка — в `app/styles/dashboard.css`. Оба файла подключаются последовательно из `main.tsx`.

Мобильное меню использует `aria-expanded`, `aria-controls` и `inert`, закрывается по Escape и при переходе, блокирует прокрутку страницы на время открытия. Скрипт `frontend/scripts/pages-smoke.mjs` проверяет статическую сборку на ширинах 320, 360, 390, 768, 1024, 1440 и 1920 px, маршруты матча и профиля, перезагрузку, выбор игрока, меню и отсутствие запросов к API.

```bash
CS2_PAGES_URL=http://127.0.0.1:4174/cs2_shark_a/ node frontend/scripts/pages-smoke.mjs
```

Пример запуска предполагает уже работающий HTTP-сервер с собранными файлами. Скриншоты по умолчанию сохраняются в `test-results/pages`; путь можно задать через `CS2_SCREENSHOTS_DIR`.

Референсы для обсуждения первого экрана, навигации и акцентов: [Supahero](https://supahero.io/), [Navbar Gallery](https://navbar.gallery/), [CTA Gallery](https://cta.gallery/). Их общие приёмы адаптированы к рабочему аналитическому интерфейсу.
