# Steam и история CS2

По последнему запросу пользователя MVP расширен поверх исходной спецификации: Steam OpenID, локальная сессия, Game Authentication Code, синхронизация истории, личный дашборд. Исходные документы сохранены; исключение Steam из первого этапа больше не ограничивает этот этап.

## Путь пользователя

1. Открыть приложение и нажать «Войти через Steam». Внешний переход ведёт только на `https://steamcommunity.com/openid/login`. Пароль приложение не получает.
2. В разделе «Подключение CS2» ввести Game Authentication Code из [личных данных CS2](https://steamcommunity.com/my/gcpd/730/?tab=accountmain) и sharing code недавнего матча из игры. Steam Guard, пароль и Steam Web API key в эту форму не вводятся.
3. При настроенных server API key и GC worker подключение запускает синхронизацию и открывает дашборд. Иначе страница честно показывает отсутствующие компоненты; доступен ручной импорт.
4. Дашборд показывает ваш Steam-профиль, последние доступные матчи, личные K/D/A, ADR, HS% и подтверждённый результат. Матч открывает таблицу участников/раунды; игрок — профиль и историю в вашей локальной выборке.
5. «Обновить матчи» получает следующие коды, скачивает доступные записи и разбирает их. Отсутствующие демки не превращаются в вымышленные показатели.

## Настройка оператора

`STEAM_PUBLIC_URL` должен совпадать с адресом, открытым в браузере, включая порт. Для Vite — `http://127.0.0.1:5173`, для Compose — `http://127.0.0.1:8000`. Не меняйте hostname во время входа: cookie состояния привязана к браузеру. Если используется HTTPS, session/state cookies получают Secure.

Вход OpenID работает без API key; без него вместо публичного ника отображается SteamID. `STEAM_WEB_API_KEY` из [Steam](https://steamcommunity.com/dev/apikey) хранится только в backend environment и нужен для публичного профиля и `ICSGOPlayers_730/GetNextMatchSharingCode/v1/`. Запрос использует `steamid`, `steamidkey`, `knowncode`, `key`. Начальная запись и последующие доступные sharing codes сохраняются в SQLite; за один запуск обнаруживается максимум 20 следующих кодов. Обновление можно повторять. Steam не отдаёт всю произвольную прошлую историю.

Sharing code не содержит URL демки. Нужен Steam Game Coordinator worker с настоящей SteamClient-сессией: [инструкция](../gc-worker/README.md). `CS2_GC_URL` — внутренний адрес worker; `CS2_GC_SECRET` — общий случайный секрет backend/worker. QR-авторизация worker выполняется локально, не в чате. Game Coordinator — клиентский протокол Valve, не обычный OpenID/Web API. Live-совместимость требует настоящего подключения.

По умолчанию `CS2_REQUIRE_STEAM_LOGIN=true`. Для полностью автономного анализа своих файлов без Steam задайте `false`. В этом режиме локальный доступ не требует входа; автоматическая история по-прежнему требует подтверждённый аккаунт. Приложение привязано к localhost по умолчанию.

## Хранение и ограничения

SQLite v2 мигрирует старые матчи без потери данных. Сессии сохраняются как SHA-256 hashes случайных opaque tokens, имеют срок 7 дней и отзываются при выходе. OpenID state живёт 10 минут, связан с cookie; проверяются exact return URL, endpoint, identity, signed fields, свежесть/replay nonce и direct Steam signature verification. Mutating-запросы авторизованной сессии требуют CSRF header.

Game Authentication Code шифруется Fernet. Ключ `CS2_SECRET_KEY` задаётся оператором или генерируется в `CS2_DATA_DIR/.cs2-secret-key` с правами `0600`. Сохраните ключ вместе с резервной копией SQLite: без него код придётся подключить заново. API никогда не возвращает сохранённый auth code, refresh token или Web API key. «Отключить» удаляет доступ и sharing-code queue; разобранные матчи остаются.

Запросы авторизованного аккаунта ограничены его импортами и матчами, где он участвовал. Статистика других участников рассчитывается по этой доступной выборке; глобальная Steam-история посторонних игроков не запрашивается. Скачанный матч прикрепляется к аккаунту только после подтверждения его SteamID в демке. SHA-256 дедупликация общая по содержимому.

Демки скачиваются только с публичных `replay*.valve.net/730/*.dem[.bz2]` без перенаправлений. Ограничены сжатые/распакованные байты, архив должен содержать ровно один полный поток. Удалённые Valve записи отмечаются недоступными и не блокируют следующие. Рейтинг Premier и события, которые адаптер не рассчитывает, не появляются из одного лишь Steam-профиля.

GC может вернуть надёжную Unix-дату матча; она сохраняется отдельно от времени импорта. История сортируется по дате матча, а при её отсутствии — по импорту. При смешанных источниках это не полная официальная история аккаунта.

## Что требует настоящего аккаунта

Автотесты проверяют OpenID/CSRF/сессии, HTTP discovery/download, GC-message correlation и UI на контролируемых ответах. Native-парсер отдельно и через BZip2 pipeline проверяется настоящим replay. Для live-приёмки нужны ваш вход Steam, Web API key, Game Authentication Code, sharing code и GC SteamClient-сессия. В этой среде их нет; успешная live-авторизация и доступность конкретных ваших матчей не заявляются.

Документация Valve: [Steam OpenID](https://partner.steamgames.com/doc/features/auth), [доступ к истории](https://developer.valvesoftware.com/wiki/Counter-Strike:_Global_Offensive_Access_Match_History). Библиотеки: [steam-user](https://github.com/DoctorMcKay/node-steam-user), [globaloffensive](https://github.com/DoctorMcKay/node-globaloffensive), [steam-session](https://github.com/DoctorMcKay/node-steam-session).
